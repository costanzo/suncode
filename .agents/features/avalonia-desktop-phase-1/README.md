# Avalonia Desktop Phase 1

**Status:** Implemented and focused-tested

SunCode's only Phase 1 production client is the .NET 10 Avalonia application under `apps/desktop-avalonia/`. C# and XAML own presentation and transient interaction state; the client calls the Rust SDK through a hand-written P/Invoke adapter and never opens SQLite, contacts providers, reads project files, invokes Git, or executes operations directly.

## Implemented workflows

- Project hub, recent/open projects, independent project windows, duplicate-window activation, a Workspace title-bar project switcher, and project-scoped session create/select/rename/pin.
- Session archive management: active sessions stay in the Sessions list, and archived sessions appear in a bottom overlay drawer inside the Sessions pane. Archive, restore, and permanent delete each require confirmation. Rust rejects archiving running or waiting sessions. It also rejects renaming archived sessions or submitting to them, and they open read-only. Restore returns a session to the active list and selects it for editing. Permanent delete is available only for archived primary sessions. It runs in one Rust transaction that removes the session, its child sessions, and all session-owned records, then makes a best-effort deletion of image files inside the configured SunCode image directory. User source images are never deleted.
- Desktop UI state restoration through one versioned `ui-state.json` in the SunCode data directory. All windows share the file, and writes are debounced and atomic (temp file plus replace). For each project it stores normal window bounds, maximized or full-screen state, navigation and review widths, bottom-drawer height, enumerated left (`closed`/`sessions`/`explorer`), right (`closed`/`review`), and bottom (`closed`/`git`/`providerTrace`/`toolActivity`) regions, and up to 20 recent-content entries. A file entry stores only an optional dependency ID and a root-relative path; a session entry stores only its SDK session ID. Settings restores its last page, provider subsection, and navigation expansion. Restored geometry is clamped to an available display. Unknown values fall back to defaults. A corrupt file is copied to a timestamped backup and startup never fails because of it. Archived or removed sessions, removed dependencies, and unreadable restored files fall back to a valid session. This is presentation state only and stays outside agent SQLite.
- Conversation streaming with atomic snapshot-plus-dormant-subscription establishment, callback activation only after presentation state is ready, latest-selection-wins loading, lagged-subscription resync through the same atomic path, stable variable-height layout, copyable final responses, expandable process history, cancellation, queued input, and retryable loading errors.
- Workspace footer upload and download rates for active built-in LLM provider body transfers, with provider/model and cumulative byte details in the tooltip.
- Hierarchical provider-and-model selection through one chat-composer menu, collapsible Settings provider navigation, editable and resettable provider URLs, credential status/store/remove, project default model, reasoning-effort control, tool-call budget, dark/light theme, and persisted diagnostics/logging settings.
- Appearance includes a persisted global interface-language selector for English and Simplified Chinese. The Avalonia localization path updates every open desktop window immediately, including Workspace navigation, conversation actions, review panels, Tool activity, Provider trace, Git review, child-session details, and read-only editor states. It uses stable `en-US` / `zh-CN` locale values for future expansion; provider and operation error text remains data-driven.
- Network Settings includes global no-proxy, system-proxy, and custom HTTP/HTTPS proxy modes with write-only Basic credentials and multiline bypass rules, alongside the existing HTTPS certificate controls.
- Language Server Settings manages global local-stdio definitions, project runtime status, language scope, enable/retry/edit/delete actions, and write-only environment patches through the embedded SDK. It does not make the read-only editor editable.
- Approval deny, allow-once, and allow-for-session flows with readable scope/action details, raw request inspection, and persistent Full Control warning state.
- Structured question prompts with single-select, multi-select, custom answers, submit/skip, snapshot restoration, and live events. Current-turn todos restore from normalized conversation snapshots and update live.
- Turn-grouped Tool activity inspection with live best-effort output, compact current-tool conversation jump, touched paths, checkpoints, conflict-aware undo, runtime health/diagnostics, provider trace drawer, Git status/diff review, and read-only project/dependency Explorer with a syntax-highlighted file viewer.
- Conversation history moves to the newest message once when entering a session. Subsequent live updates preserve the user's viewport; returning to the latest message is an explicit action.
- Responsive navigation and review bays, in-window dialogs, keyboard toggles, native macOS menu integration, and the shared design-system review pages under `design-system/`.
- Built-in Agents settings navigation and read-only catalog details, plus a Child sessions right bay, ContentSwitcher entries, read-only central timelines, and inline child-operation approvals.

The desktop logger opens its default rotating `desktop.log` during process startup, before persisted settings load. SDK operations and ViewModel actions record error-level failures with operation names; process, task, and Avalonia dispatcher unhandled exceptions are recorded with bounded, single-line exception chains. Diagnostics exclude credentials, prompts, model responses, tool inputs/results, file contents, and raw native envelopes.

View models are being split from the single partial `DesktopViewModel` into composed feature view models. Each window's `DesktopViewModel` exposes feature children (currently the Settings children `Mcp`, `LanguageServers`, `Network`, and `Remote`, plus the Workspace drawers `Git`, `ProviderTrace`, and `ToolActivity`, the Workspace `Editor`, `Explorer`, and `Layout`, the `Browser` and `Computer` runtime controls, `RecentContent`, and the footer `ProviderTraffic` and review `ContextUsage`) that reach the SDK, selected project, and error, status, and busy reporting only through the narrow internal `IViewModelHost`; shared settings reads go through `SettingsSnapshot`. The Settings window binds to a `SettingsWindowViewModel` that composes those children with Settings-only edit state (`Defaults`, `Appearance`, `Logging`, `NetworkEditor`, `RemoteEditor`); each page tracks its saved baseline so Save commands are enabled only while that section is dirty. `SettingsNavigationViewModel` owns the selected page, navigation highlight, provider/agent expansion, and persistence, and makes the visible page the single target of one shared 2-second `PagePoller`. Status colors are exposed as `StatusTone` values mapped to theme brushes by `tone-*` style classes. The model-provider panel is still driven from window code-behind. Children that need session context use the narrower `IProviderTraceHost` extension rather than widening the shared host. `WorkspaceLayoutViewModel` (`Layout`) owns pane, drawer, gutter, and breakpoint state, the toggle rules (collapsed regions reopen at their default size; bottom drawers are mutually exclusive), and resize clamping; it signals persistence through events so `DesktopViewModel` keeps sole ownership of the UI state store. Workspace traffic lights are `TrafficLightButton` controls with an explicit `Kind`. Appearance, locale, logging, and image-storage settings live in one App-owned `AppSettingsViewModel` shared by every window view model. The Project hub binds to `ProjectHubViewModel`, a narrow surface over a project-less `DesktopViewModel` that still backs the Settings window opened from the hub. Views bind the child as their `DataContext` or through a dotted path. Remaining partial files migrate incrementally; the split is not complete.

Source layout: `Views/` is organized by window role (`ProjectHub`, `ProjectWorkspace`, `Settings`, `DialogWindow`, `About`, `Shell`). `Models/UiModels/` is split by feature. Application styles and theme resources live in named files under `Styles/Application/`, and localized strings live under `Resources/Localization/`. Shared `SC*` controls in `Controls/` cover file/folder selection with suffix filters (`SCFileSelector`), flat and grouped selectors used by Settings and the composer model picker (`SCFlatComboBox`, `SCGroupComboBox`), numeric input, status dots, and a reusable modal (`SCModal`) with Escape/backdrop dismissal, focus containment and restoration, and a scrolling header/body/actions layout. Feature views consume these controls and the semantic theme resources instead of local markup or raw values.

## Boundary and verification

### Visual implementation notes

- Shared Avalonia theme resources use the design-system's neutral graphite/silver primary action palette with separate success, warning, and danger semantics in both dark and light themes.
- The desktop has five top-level window roles: ProjectHub, Workspace, DialogWindow, Settings, and About. Workspace alone uses `WindowDecorations=BorderOnly` with the 36 px custom title-bar content and compact traffic lights while delegating the outer border and resize behavior to the platform; it has no transparent outer margin, rounded frame wrapper, or manual resize handles. On macOS, double-clicking its title bar toggles normal and maximized states, while the green traffic light remains the full-screen action. ProjectHub, DialogWindow, Settings, and About use full system decorations without duplicate client-side title bars. DialogWindow hosts secondary confirmation and opens its dialog only after an explicit user action.
- About identifies the installed Desktop and Agent SDK releases with separate `vX.Y.Z` values. Desktop uses its .NET assembly metadata; Agent SDK queries the Rust agent core version through the Rust facade, C ABI, and managed binding. The Agent SDK product version is distinct from the C ABI compatibility number.
- ProjectHub uses a 62 px toolbar, 70 px recent-project rows, 24 px content insets, and a compact first-run empty state. The project workspace uses 4 px shell gaps, 34 px gutter columns containing 26 px controls, 272/312 px default side panes, mutually exclusive bottom drawers, and a 20 px status bar.
- The Workspace title-bar project switcher keeps Open project as its first action and lists recent project names and paths without exposing window-open status. It uses the ProjectHub folder-picker flow; selecting a recent project creates its Workspace window or activates the existing one.
- The centered Workspace title identifies the active central content: a session title for Conversation or a file name for Editor. Its dropdown keeps up to 20 unique, most-recent-first files and sessions per project, restored across restarts through desktop UI state, omits the current item while retaining it internally for later history, distinguishes types with text, icons, and restrained semantic color, and switches through the existing session/file selection paths without adding agent persistence or file mutation authority.
- Sessions use 48 px rows with fixed pin/status/action columns and a compact empty state. Explorer uses compact 24 px tree rows, native chevrons, root/dependency semantic styling, monospace path subtitles, and horizontal scrolling for deep paths.
- Selecting an Explorer file replaces Conversation in the Workspace center with a transient read-only AvaloniaEdit document. The 44 px header retains file identity, detected language, and read-only status; TextMate supplies light/dark syntax highlighting, while line numbers, selection, and horizontal scrolling remain available. Loading, empty, and bounded-read failures keep the same non-editable frame. Selecting any session, including the current session, restores Conversation.
- Conversation uses 14 px assistant Markdown and 14 px composer draft text, right-aligned user message bubbles, compact process/tool rows, a 24 px no-session empty treatment, a recycling history container, an active-turn work indicator, and an animated `Thinking` label during the thinking phase. The composer can expand into a workspace-root modal with a larger draft and a live character count. For models advertising image input, up to three bounded images can be uploaded from file or clipboard, previewed, removed before submission, submitted as message-owned references, and restored above their owning user message. Non-vision models keep image selection disabled. Uploaded images are persisted through the SDK as session-owned files under the configurable global image directory, which defaults to `<data directory>/data/images/{sessionId}/`. SQLite keeps their metadata and thumbnails.
- Tool activity is a bottom drawer, mutually exclusive with Source control and Provider trace. It shows a two-level Turn → tool-call tree with a detail pane. The active turn is expanded and the active tool is selected by default. Live output follows the tail until the user scrolls away. Conversation shows only messages and turn separators, whose hover preview shows the start of the user prompt, plus at most one compact active-tool row that jumps to its detail.
- Review prioritizes approval and question requests before turn changes, touched files, runtime health, todos, and checkpoints. Git and provider trace use compact semantic hierarchies. Settings uses a 238 px surface-backed navigation column, 58 px toolbar, 32 px navigation rows, 30 px provider rows, shared two-column setting rows with a 220 px control column, provider overview and detail pages, megabyte log sizing, image storage, a 720 px content cap, 11 px hints, and compact warning/credential surfaces.
- Responsive workspace presentation hides review below 1100 px, navigation below 860 px, and gutters, drawers, and status details at 620 px or below while preserving user visibility preferences for restoration.

Native calls run off the UI thread, subscription payloads are copied and marshalled to `Dispatcher.UIThread`, and subscriptions close before the shared runtime handle. Focused tests are colocated under `apps/desktop-avalonia/tests/` and run with:

```text
dotnet test apps/desktop-avalonia/tests/SunCode.Desktop.Tests.csproj
```

Not implemented: file editing in the Editor, interface locales beyond `en-US` and `zh-CN`, and localization of provider and operation error text, which stays data-driven by design. Known gap: the review panel's changed-file list accumulates across the session while its empty state says "No files changed in this turn"; per-turn `changedPaths` from the snapshot is not yet used there.

The native Rust CLI administrative foundation is implemented separately and does not change this desktop boundary. Its conversational/session workflows and all TUI, Web, mobile, IDE-plugin, hosted, and Electron surfaces remain deferred.
