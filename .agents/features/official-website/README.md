# Official Website

**Status:** Implemented and build-verified

`website/` is the public, server-rendered Next.js site for `suncode.ai`. It explains the product and links to the public GitHub repository. Deferred Web, TUI, IDE, and hosted execution surfaces are not presented as available clients. Existing marketing copy is not an authoritative feature specification; use [`WEBSITE-CLAIMS.md`](../WEBSITE-CLAIMS.md) when regenerating it.

The overview now demonstrates project inspection, scoped approval, and checkpointed file review through three explicitly illustrative, user-controlled stages. Supporting content covers project context, Skills, language servers, documents, CLI/SDK workflows, and paired mobile control. Undo language is limited to checkpointed mutations, and current Git review is described separately from agent operation authority. No download or universal provider-compatibility claim is introduced.

`/features` maps all 31 durable feature records into seven reader-facing groups. It provides text search, availability filtering, category anchors, live result counts, empty recovery, and per-entry scope disclosures linked to the owning technical record. Implemented, Preview, Release verification, and Developer tooling are distinct states. `website/lib/feature-catalog.json` owns the public editorial mapping; focused coverage tests fail when records are missing, duplicated, or lack valid groups/status/scope.

The site uses the Next.js App Router and TypeScript, includes shared responsive navigation, canonical/Open Graph metadata, sitemap and robots routes, and reuses the SunCode brand assets. Self-hosted Noto Sans and JetBrains Mono carry the graphite/silver visual system. Root `DESIGN.md` and `design-system/` → Projects → Official website specify desktop/mobile composition, menu dismissal, focus, filtering, disclosure, reduced motion, and empty states. It is separate from the Web remote-control specimen and the deferred Web client.

The header offers light/dark switching on desktop and mobile. Without a saved choice, the site follows system appearance; manual choices persist in localStorage and synchronize across tabs. A head bootstrap applies the choice before first paint. Both page content and the workbench use theme-specific tokens, including logos, actions, code, and availability colors; storage failure preserves switching for the visit.

Build and verify from `website/` with `pnpm build`, `pnpm typecheck`, `pnpm test:features`, `pnpm test:theme`, and `pnpm test:updates`. `website/README.md` documents content maintenance and browser checks. Local implementation and validation do not establish a production deployment.

The 2026-11-05 update passed the Next.js production build/type check, all 19 feature-coverage and update tests, the design-system build, focused specimen formatting, and diff checks. Browser review covered desktop and 390px mobile layouts, workflow switching, combined search/availability filters, empty recovery, scope disclosure, mobile menu Escape behavior, and the matching light/dark catalog specimen. The observed mobile guide overflow and unqualified homepage mobile claim were corrected and passed a separate source/screenshot review.

The public `/updates/v1/stable/{target}/latest.json` route serves Desktop component catalogs from checked-in files with JSON content types, ETag/304 handling, and bounded HTTP caching. The six target files are normally served signed 0.1.0 catalogs with First release notes. Per the approved development setup, package URLs/sizes/hashes are sample values; actual component archives do not yet exist. Desktop catalog checking is enabled against `https://www.suncode.ai`, with both apex and www download origins allowed. Valid signatures do not establish usable downloads or installed-package conformance. An offline Node/TypeScript publisher computes real archive hashes/sizes, checks the signer against Desktop pinned public keys, copies immutable archives under `public/updates/releases`, and signs/replaces the catalog. Website deployment has no private signing key and performs no Agent or installed-version decision. See [`website/updates/README.md`](../../../website/updates/README.md) for publication/renewal and `pnpm test:updates` for focused verification. Repository changes require rebuilding/redeploying the existing website; no production deployment or signed installed-package conformance is claimed.
