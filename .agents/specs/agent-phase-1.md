# Agent Phase 1

Tool execution hardening keeps the compact model contracts aligned with audited behavior: `read` applies 1-indexed line ranges before its byte cap, `glob` respects ignore rules, `edit` preserves BOM and line endings while rejecting overlaps, and failed bash exits are represented as failed tool operations with structured status.

The agent is an embedded Rust SDK inside its host process with one SQLite database under `~/.suncode/data/sqlite/agent.sqlite3`.

The native Rust CLI under `apps/cli` embeds `AsyncAgentSdk` on its Tokio runtime. One-shot `run` creates a primary session, while `session resume` reopens an existing primary session and adds one turn using its durable conversation context. Both establish atomic session watch before submission, render typed events, drain already-published events before the final result, request cancellation on the first interrupt, and consume explicit SDK shutdown. Text mode reserves stdout for the final assistant response and writes progress to stderr; JSONL mode emits versioned event envelopes followed by `run.result` or `session.resume.result`. The Rust facade exposes an optional pending approval for a validated session; resume combines that with snapshot `pendingQuestion` and returns exit status 4 rather than submitting through a suspended interaction. Session list/archive remain SDK-owned lifecycle adapters. Interactive chat and continuation prompts are not implemented.

The `suncode-data` Cargo package under `agent/crates/data` owns the Diesel SQLite store, persistence DTOs, ORM schema, and table operations. The `suncode-database` package under `agent/crates/database` owns backend-specific SQL resources and database-file setup; its SQLite implementation is under `suncode_database::sqlite` and does not depend on Diesel. The `suncode-agent` core package consumes `suncode-data` and does not depend on a database driver directly.

The `suncode-llm` Cargo package under `agent/crates/llm` owns the LLM provider trait, provider-neutral request and response types, model metadata and registry, built-in catalog, and OpenAI-compatible HTTP/SSE adapter. It has no dependency on `suncode-data`, `suncode-database`, `suncode-agent`, or `suncode-tool`. Its registry accepts owned custom provider/model identifiers and trusted `Arc<dyn LlmProvider>` implementations. The Rust SDK facade implements the private SQLite-backed credential resolver and catalog-to-provider DTO conversion at the agent composition boundary; agent core does not expose a second credential store.

`AsyncAgentSdk` startup acquires the agent lock, opens the database, performs recovery, and exposes named in-process methods plus live event subscriptions on the caller's Tokio runtime. It contains no `Runtime` and calls no `block_on`. `SdkOpenOptions` maps immutable Browser and Computer capability ceilings into core composition; defaults enable both, disabled capabilities retain persisted desired state for diagnostics but advertise no model tools, initialize no external backend, and reject management mutations before persistence. Its consuming `shutdown().await` marks core closed, rejects new submissions and approval/question continuations, cancels active turn tokens, clears queued input, stops Computer Use, drains Browser/MCP/LSP resources, waits up to five seconds for active turns, closes event subscribers, and releases the data-directory lock when the facade is dropped. Pure SQLite/DTO operations remain synchronous. The compatibility root `AgentSdk` is `blocking::AgentSdk`: it owns one runtime, dereferences to the async facade for synchronous methods, adapts awaited operations, and keeps the runtime alive while its consuming shutdown awaits cleanup. C embeds that adapter with default host capabilities and native close invokes shutdown. There is no client-facing listener, HTTP authentication token, endpoint discovery record, or standalone agent binary. Core retains non-exhaustive typed `AgentEvent` payloads and publishes them through bounded session-scoped queues. The Rust facade exposes a typed `SessionEventStream` implementing `Stream<Item = Result<Arc<AgentEvent>, SubscriptionError>>` and `FusedStream`, plus direct async, blocking, and nonblocking receive methods. Normal close is end-of-stream; lag yields one typed error and then terminates. `watch_session` registers that stream and reads the normalized snapshot under the same per-session in-memory gate used by event projection-plus-publish and live-only publication. A notification cannot fall between the returned snapshot and stream. Some normalized lifecycle writes, including turn admission, intentionally precede their corresponding notification projection, so hosts continue to apply events idempotently. Snapshot failure unregisters the provisional subscriber. The native ABI exposes atomic `watch_session` plus single-use `subscription_start`; C returns snapshot JSON with a dormant opaque handle, and C# exposes typed `SessionWatch`. Avalonia applies the snapshot and auxiliary state, verifies the load version, installs the watch, and only then starts the callback worker. Stale and failed loads dispose dormant handles. The C binding owns the callback worker, JSON envelope, raw callback pointer, lag-to-`resync.required` translation, and log-only shutdown error adaptation. Rust diagnostics are emitted at SDK FFI and turn-continuation boundaries with safe operation labels, codes, retryability, provider request IDs, and session/turn IDs where available; FFI arguments and user/provider content are excluded. Session context is built from timestamp-ordered `session_message` user/assistant/thinking rows plus transient tool-role messages derived from succeeded `session_tool_use` results; streaming and lifecycle events are not stored as a duplicate journal. Provider-reported usage updates the cumulative `session_turn` projection, and the named session-usage method returns the sum across turns without estimating missing provider usage. Each provider request is stored in `session_call` without its model request message payload, including independently nullable provider HTTP request and response-object identifiers when reported; each tool request/result is stored in `session_tool_use`, and normalized provider traces remain available through the existing SDK methods. Trace summaries contain every session turn and its calls; call detail joins correlated readable messages and tool uses but never exposes the model request payload. OpenAI-compatible cache-read, cache-miss, cache-write, and reasoning usage is normalized and retained on the call when reported. The session snapshot retains its flat message compatibility projection and adds correlated conversation turns containing normalized messages and tool uses so clients can rebuild process timelines without opening SQLite. Lagged primary-session clients repeat the atomic watch load path.

Provider context reloads a bounded project-root `AGENTS.md` as a system message before every model call. Successful project file reads add unseen nested `AGENTS.md` guidance nearest-first to `repository_instructions` in the normalized read result. Discovery stays inside the canonical project, excludes dependencies and direct instruction-file reads, and is bounded to 32 KiB per file, 16 nested files, and 64 KiB per read.

Provider integration is Rust-owned. The Rust SDK facade loads enabled rows from `llm_model_provider` and `llm_model`, selects the known `suncode-llm` adapter named by `adapter_type`, and passes owned model descriptors to the registry. The provider-table constraint accepts `openai` for OpenAI-compatible endpoints and `anthropic` for the built-in Claude Messages route and native client toolsets; custom providers default to the OpenAI-compatible adapter. Opening the immediately previous current-schema table that accepts only `openai` transactionally rebuilds only that table, copies all provider rows, drops the legacy table, and then switches the unchanged built-in Claude endpoint from `openai` to `anthropic`. Provider API keys are loaded exclusively from `llm_model_provider.api_key`; provider credential environment variables are ignored in every execution mode. Context construction uses persisted `context_tokens` and `auto_compact_tokens`.

First-party Computer Use is an in-progress Rust-owned capability independent of MCP and Browser Use. The core advertises Claude's native client toolset only when global enablement, backend availability, and the selected model's `supports_computer_use` capability are all true. Input-producing actions remain interactive approval gates even under Full Control; non-interactive execution rejects them. Screenshot bytes are transient provider context and durable rows retain redacted metadata only.
Models also advertise `capabilities.reasoning_effort` and their persisted `reasoning_efforts` catalog. The Avalonia client offers the selected model's advertised effort values only when this capability is enabled. Turn admission validates the value, selects the first advertised effort when the caller omits it, snapshots the normalized value, and atomically persists it with the selected model on the session; the OpenAI-compatible adapter sends it as `reasoning_effort` when present.

Models advertise image input through `capabilities.vision`. Attachment-aware turn submission accepts at most three unique same-session image IDs and validates the persisted file, supported image extension, 20 MiB limit, and model capability before admission. The durable user message stores `image_ref` parts, while provider context resolves them to OpenAI-compatible `image_url` data URLs just before a model call. Provider diagnostics replace image data with a redacted marker. Text-only callers remain compatible through the original method, and image-bearing input is rejected instead of queued while another turn is active.
Configuration is stored in one table and resolves global, project, and session values in that order. When no model is supplied for a new session or turn, core uses the project's effective `default_model` setting and falls back to the default seeded model only when no configured value exists. The project-only `tool_call_limit` is an integer from 1 through 256 and defaults to 64. The global `image_directory` setting is a string and defaults to the empty value, which resolves to `<data directory>/data/images`. Core snapshots the turn tool-call limit at admission and rejects an entire provider-returned tool batch before policy or execution when accepting the batch would exceed the limit.

Global `verify_https_certificates` is a JSON boolean seeded as `true`. Core loads it fail-safe, shares one atomic current value with the built-in OpenAI-compatible adapter and operations dispatcher, and updates that value after a successful SDK write. Each subsequent provider or WebFetch request uses the current value; an in-flight request is unchanged. `false` configures reqwest to accept invalid certificate chains and hostnames. Trusted custom provider implementations do not automatically inherit this setting.

Global proxy settings use `proxy_mode`, `proxy_url`, `proxy_username`, `proxy_password`, and `proxy_bypass` rows in `configuration`. `proxy_mode` defaults to `system` and accepts `no_proxy`, `system`, or `custom`. A named SDK operation validates and writes the complete proxy configuration atomically; generic setting writes cannot mutate proxy keys. Settings reads omit `proxy_password` and synthesize `proxy_password_configured`. Custom mode accepts one HTTP or HTTPS proxy without embedded URL credentials, applies optional Basic authentication, and combines user bypass entries with mandatory localhost, IPv4 loopback, and IPv6 loopback exclusions. PAC, WPAD, SOCKS, and integrated authentication are unsupported. Subsequent built-in provider and WebFetch requests use the live snapshot, while active remote HTTP MCP connections reconcile against the persisted snapshot. In-flight requests are unchanged.

Projects may register additional read-only source dependencies. Their canonical roots remain in Rust-owned `project_dependency` rows, while SDK clients receive only stable dependency IDs and display names. Directory browsing is shallow, bounded to 500 entries, ignores symlinks, and is loaded on demand. The named `read_project_file` SDK method selects the main project or a registered dependency by stable ID and returns one root-relative regular UTF-8 text file up to 1 MiB; it rejects path escapes, symbolic-link file entries, NUL-containing/binary content, and oversized files without returning partial content. Agent `read`, `glob`, and `grep` calls accept `dependency:<id>/...` and return paths with that alias intact; all mutation, process, Git, and checkpoint operations remain scoped to the main project.

The model-facing tool registry exposes `read`, `glob`, `grep`, `question`, `todowrite`, `write`, `edit`, `bash`, `webfetch`, `lsp_diagnostics`, `lsp_definition`, `lsp_references`, `lsp_hover`, and `lsp_symbols`. The five LSP tools are fixed read-only schemas, accept project/dependency paths and optional language IDs, use one-based positions where applicable, and return bounded normalized semantic data without exposing arbitrary external absolute paths. They synchronize at most 1 MiB of UTF-8 text through the existing authorized read operation. `question` pauses the current turn for structured user input. `todowrite` is a read-only current-turn list replacement with up to 100 prioritized items, at most one `in_progress` item, and a `todo.updated` event. Its authoritative progress is stored in `session_turn_todo` and returned as `conversationTurns[*].todos`; the normalized `session_tool_use` result remains call history. The OpenCode-compatible `bash` tool requires `command` and accepts optional `timeout` in milliseconds (positive, maximum 600000) and `workdir`; it uses Windows PowerShell on Windows and POSIX `/bin/sh` on macOS and Linux. `webfetch` requires an HTTP(S) URL and accepts optional `format` (`text`, `markdown`, or `html`, default Markdown) and seconds-based `timeout` (default 30, maximum 120). Core validates those arguments before requesting network approval, and the operations boundary validates them again. Redirects are limited to the approved host and port or a standard HTTP-to-HTTPS upgrade. Textual responses are bounded to 5 MiB, decoded using BOM or declared charset, converted from HTML where requested, and limited to a 64 KiB model preview with the complete converted result stored as a managed artifact. Binary and image content is rejected because the current model tool-result contract has no attachment channel. Windows child processes use `CREATE_NO_WINDOW` so desktop execution does not allocate or flash a console window. Process execution remains approval-gated, uses a filtered environment, keeps its working directory inside the opened project, continuously drains output streams, retains a bounded tail preview, and exposes oversized output through a complete artifact. Turn cancellation propagates into the process runner, which terminates the Unix process group or Windows process tree before returning. Recoverable argument, MCP, and LSP failures are recorded as failed tool results and fed back to the model so the same turn can regenerate or fall back; non-recoverable authorization, approval, and agent failures still terminate the turn. Each provider request receives host context containing the target OS, architecture, shell dialect, path style, and stable session-start timestamp. Retired operation names fail closed and are no longer executable.

When global `browser_use_enabled` is true and the exact bundled runtime is present, primary sessions additionally advertise `browser_open`, `browser_snapshot`, `browser_navigate`, `browser_click`, `browser_fill`, `browser_press`, `browser_tabs`, `browser_screenshot`, and `browser_close_page`. Child sessions never receive them. The Rust agent validates the runtime lock and tree hashes, starts one lazy project worker, retains a project-isolated profile, accepts only semantic locators or revision-bound references, stores bounded screenshots as managed PNG artifacts, and records calls through the ordinary tool lifecycle. Browser calls always require interactive approval, remain denied non-interactively, and are not bypassed by general Full Control. Page content is untrusted, only credential-free HTTP(S) navigation is accepted, cancellation retires the worker, and website/profile changes are outside filesystem undo.

Approval decisions are `deny`, `allow_once`, and `allow_session`. `allow_session` updates the pending approval and session-scoped `configuration.full_control=true` in one database transaction. Policy reads that boolean for every call and allows known project-write, process, network, and destructive-write risks without another approval while it is enabled. Full Control never authorizes an unknown tool, never pre-authorizes Browser Use, and does not bypass argument translation, canonical paths, dependency or URL restrictions, audited dispatch, checkpoints, or cancellation. Writing `false` through the SDK settings boundary disables it for subsequent calls.

The primary model-facing catalog also includes core-owned `delegate_agent(agent, task)`. Its agent enum is the immutable catalog of `architect-agent`, `ui-ux-agent`, `product-agent`, `swe-agent`, `qa-agent`, and `sre-agent`. Delegation creates one child session and one `session_subagent_invocation`. Child continuations inherit model and reasoning effort, share parent cancellation while active, and use the smaller of the project tool-call limit and their role limit. Architect, UI/UX, and Product allow `read`, `glob`, `grep`, `webfetch`, and `todowrite` with a 32-call ceiling. SWE, QA, and SRE additionally allow `write`, `edit`, and `bash` with a 64-call ceiling. All child requests exclude MCP, `question`, and `delegate_agent`; execution independently rejects any call outside the snapshotted allowlist.
