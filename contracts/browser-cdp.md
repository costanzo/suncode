# Browser CDP Contract

The Avalonia client owns one CEF Chromium instance per application and configures `RemoteDebuggingPort` on localhost (default `9222`) only when a browser surface is first needed. Desktop startup does not initialize CEF. Desktop projects the global Browser Use setting into shared application state. Disabled state closes browser and preview views, collapses their panels, and hides the browser gutter and native/compact View-menu entries across project windows. Direct desktop opening and host-page requests also check this state. Browser Use tools are advertised when the host capability ceiling supports Browser Use and the global setting is enabled. A live CDP connection is not required for advertising tools. Before each Browser Use operation, Rust uses the existing Browser Host request to prepare its project page. Avalonia validates the Chromium component, initializes CEF when needed and guides missing-component recovery through Settings. Rust then connects or reuses its CDP session. Each project page has a stable opaque target marker so Rust attaches to the requesting project's page. The component checks run entirely in Avalonia before the host returns its ready/failure result, including requests made before cached CDP operations.

Desktop compiles its managed CEF binding directly into `apps/desktop-avalonia/` and installs Chromium explicitly through Settings → Browser use. NuGet.org and Huawei Cloud share the application-pinned package identity, version, target and SHA-256. The complete package must match before extraction. Installation uses bounded ZIP extraction, a file manifest, immutable payload directories, and an atomic activation pointer under `<application data>/browser-components/`. A failed or canceled replacement preserves the previous activation. Installed files are fully hashed before native loading and on explicit verification. Lightweight availability checks validate the active manifest and file presence/sizes. A loaded native runtime requires application restart before a staged replacement can activate. After a successful replacement, Desktop removes inactive installations except the runtime loaded by the current process. Primary Desktop startup collects superseded installations under the installer lock after acquiring the application instance lock. Cleanup preserves the active installation, defers files still in use, and leaves installations intact when active metadata is invalid.

The existing `suncode_agent_sdk_set_browser_host_callback` interface remains at ABI 28. A successful host request means that the project page is ready for CDP. The callback must be idempotent; Avalonia reuses initialized pages without reopening the browser panel or changing the selected tab. The host owns Chromium packages, manifests, hashes, native loading and installation guidance. Component-specific states stay in Desktop. Rust consumes the ordinary host success/failure result and applies its existing CDP errors, policy and host capability ceiling. Hosts with their own CDP integration may omit the callback.

The Rust `suncode-browser` crate uses `chromiumoxide` to manage the CDP WebSocket, target attachment, command correlation, and event loop. The agent applies request timeouts and converts library failures into stable business errors. Page content is untrusted and cannot authorize actions. The client owns CEF windows, resources, and the project-isolated persistent Browser Use profiles; Rust does not launch Node.js, Playwright, Chromium, or arbitrary JavaScript workers. Embedded project preview is a separate service lifecycle and is never started merely to browse an external site.

Supported Browser Use operations are mapped to CDP `Page.navigate`, `Runtime.evaluate` for bounded semantic DOM actions, `Input.dispatchKeyEvent`, `Page.captureScreenshot`, and `Page.close`. Raw CSS/XPath, model supplied scripts, executable paths, and proxy credentials are not accepted as tool inputs.
